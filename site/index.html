The operating model

One registry is the source of authority.

workspace

Each Logical Agent is bound to an administrator-selected working directory.

runtime

Claude Code or Codex is selected in host configuration, not by the Caller.

policy

Every Task runs with an explicit read-only, workspace-write, or full policy.

Use cases

Run a local coding runtime when the work calls for it.

A Caller selects a preconfigured Logical Agent. AgentPort starts the bound Runtime for a Task, keeps its progress observable, and leaves the host’s Git and GitHub choices explicit.

01 / IMPLEMENT

Hand an approved issue to a prepared workspace.

A workspace-write Agent can receive the issue and acceptance criteria as a Task, then implement and test inside its configured workspace. Updating main, creating a worktree or branch, and opening a pull request remain Git and host-runtime operations—not AgentPort controls.

submit_task → get_task
02 / TRIAGE

Investigate an issue before granting write access.

A read-only Agent can inspect its configured workspace, tests, and the issue context included in a Task. Looking up the latest GitHub issue is possible only when the Runtime has an authorised host tool and network access; AgentPort does not provide an issue API.

list_agents → submit_task
03 / SUPERVISE

Keep long-running work visible without a permanent coding session.

Long-poll a Task for state changes, inspect its final response and Git summary, send a Follow-up Task in the same Context, or request cancellation when the work should stop.

get_task → follow_up → cancel_task

AgentPort owns: configured Agents, policies, Task state, Context, queueing, and results.

The Runtime and host own: Git worktrees and branches, GitHub issue and pull-request access, credentials, and timed triggers.
