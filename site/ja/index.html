管理された MCP gateway

ローカル Runtimeを、意図どおりに制御。

AgentPort は構成済みの Claude Code と Codex workspace を Logical Agent として公開します。Caller は任意のパスや runtime を選ぶことなく、作業を dispatch し、Task を観測し、Context を継続できます。

AgentPort を導入MCP client を設定

運用モデル

単一の registry が権限の基準になります。

workspace

各 Logical Agent は管理者が選択した作業ディレクトリに結び付けられます。

runtime

Claude Code または Codex は Caller ではなく、host 設定で選択します。

policy

すべての Task は read-only、workspace-write、full の明示的な policy で実行されます。

ユースケース

作業が必要とするときに、ローカル coding runtime を実行する。

Caller は事前構成済みの Logical Agent を選択します。AgentPort は Task のために紐付いた Runtime を開始し、進捗を観測可能に保ち、host 側の Git と GitHub の判断を明示したままにします。

01 / IMPLEMENT

承認済み issue を準備済み workspace に渡す。

workspace-write Agent は issue と受け入れ条件を Task として受け取り、構成済み workspace 内で実装とテストを行えます。main の更新、worktree または branch の作成、pull request の作成は、Git と host runtime の操作であり、AgentPort の制御ではありません。

submit_task → get_task
02 / TRIAGE

書き込み権限を渡す前に issue を調査する。

read-only Agent は構成済み workspace、テスト、Task に含まれる issue context を調べられます。最新の GitHub issue の検索は、Runtime が認可済み host tool とネットワークアクセスを持つ場合に限り可能です。AgentPort は issue API を提供しません。

list_agents → submit_task
03 / SUPERVISE

常時 coding session を開かずに、長時間の作業を可視化する。

Task の状態変更を long-poll し、最終応答と Git summary を確認し、同じ Context で Follow-up Task を送信し、作業を止めるべきときはキャンセルを要求できます。

get_task → follow_up → cancel_task

AgentPort が担うもの：構成済み Agents、policies、Task state、Context、queueing、結果。

Runtime と host が担うもの：Git worktree と branch、GitHub issue と pull-request のアクセス、認証情報、時刻ベースの trigger。

小さな protocol surface

Task lifecycle 全体に必要な MCP tools は、わずか六つ。

01 / DISCOVER

Agents を一覧する

作業を dispatch する前に、構成済み Logical Agents と policies を確認します。

02 / DISPATCH

送信してフォローアップ

Task を作成し、Runtime が質問したら同じ Context を継続します。

03 / OBSERVE

待機、確認、キャンセル

Task state を long-poll し、最終応答と Git summary を確認、または安全にキャンセルします。

contract から始める

ローカルに導入し、すでに使っている MCP client からリモートで接続する。

repository を開く
ローカル coding runtime を、あなたの条件で会話に参加させる。
