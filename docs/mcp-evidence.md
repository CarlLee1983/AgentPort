# MCP 優先技術證據

查證日期：2026-09-12。來源限 MCP 官方規格／文件與官方 TypeScript SDK GitHub repository；只讀取文件與 metadata，沒有安裝 SDK、啟動 Runtime、發送 MCP 請求或改動外部服務。下列「已查證」不等於 AgentPort 已通過互通性測試。

- **推薦固定目標 revision：`2026-07-28`。** 官方 specification overview 現列 stateless、self-contained requests 與 per-request capability negotiation；官方 2026-07-28 發布說明確認此 revision 已取代 connection-scoped handshake/session 模型。`2025-06-18` 下列舊頁只作 legacy compatibility evidence，不稱為 current stable。**確定性：高。驗證：閱讀官方 2026-07-28 overview 與 release announcement。未解：Claude／generic caller 是否支援此 revision，仍需端到端 probe。** [2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28), [official release announcement](https://blog.modelcontextprotocol.io/posts/2026-07-28/)

- **2026-07-28 Streamable HTTP 是每訊息 POST，回覆可為 JSON 或 request-scoped SSE。** Transport overview 明確說每個 message 都是對單一 MCP endpoint 的 HTTP POST；SSE 是可選的 request-scoped response stream。這不表示必須維持長連線或支援獨立 GET SSE；AgentPort 可先採 stateless request/response。舊 2025-06-18 transport 的 GET 可開 SSE，但 server 也可回 405，故「endpoint 有 GET」不等於「必須提供 SSE」。**確定性：高。驗證：閱讀官方 2026 Transports 與 2025 legacy Transports。未解：正式 Streamable HTTP binding 的 HTTP status、content negotiation、proxy timeout 仍需 implementation probe。** [2026-07-28 Transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [2025-06-18 Transports／GET](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#listening-for-messages-from-the-server)

- **舊 revision 的 initialize/session 行為須與 current revision 分開。** `2025-06-18` 規格要求 `initialize` 首次互動、之後 `notifications/initialized`，且 server 可回 `Mcp-Session-Id`；若回 session ID，client 後續請求必須帶它。這是舊 protocol compatibility path 的證據，不是 2026-07-28 的 app Task 模型。**確定性：高。驗證：閱讀官方 2025-06-18 Lifecycle／Transports；官方 2026 發布說明確認 2026-07-28 retired initialize／initialized 與 `Mcp-Session-Id`。未解：是否同一 endpoint 同時服務兩個 revision、fallback matrix 需固定 SDK 後測試。** [2025-06-18 Lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle), [2025-06-18 Transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports), [2026 release notes](https://blog.modelcontextprotocol.io/posts/2026-07-28/)

- **AgentPort 應以普通 MCP tools 回傳 app Task ID；不要依賴 native MCP Tasks。** 2026-07-28 overview 將 Tasks 列為 opt-in extension；官方 current Tasks 文件描述 `taskId`、`tasks/get`、`tasks/update`、`tasks/cancel`，且 server 只在 client 宣告 extension 時回 task result。官方 release notes 另說 2025-11-25 experimental Tasks API 需 migrate 到新的 extension lifecycle，兩者不可當成同一 contract。AgentPort 可讓 `submit` tool 同步回傳自己的 durable task ID，再以獨立 `getTask`／`events`／`reply`／`cancel` tools 輪詢或操作；這是應用契約，不宣稱與 MCP Tasks extension API 相同。**確定性：高（extension 是 optional；AgentPort mapping 是 recommendation）。驗證：閱讀官方 2026 overview、Tasks extension 與 release notes。未解：generic caller 對自訂 tool catalog、事件 cursor、長期 task ID 的 UX 需測試。** [2026 overview](https://modelcontextprotocol.io/specification/2026-07-28), [Tasks extension](https://modelcontextprotocol.io/extensions/tasks/overview), [2026 release notes／Tasks migration](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

- **Polling 可用獨立 `getTask` calls，與原 submit request／MCP transport session 無關。** 官方 Tasks 文件說 task ID 可在 client disconnect/restart 後繼續 polling；這只支持「durable handle」的應用模式，未證明 AgentPort 必須採 native `tasks/get`。**確定性：中高。驗證：閱讀官方 Tasks overview 的 durable handle／polling 段落。未解：AgentPort 跨重啟持久化、授權 ownership、事件 replay／cursor、TTL 尚未由 MCP 規格規定。** [Tasks overview](https://modelcontextprotocol.io/extensions/tasks/overview)

- **標準取消與 app Task 停止是兩層語意。** 2025-06-18 `notifications/cancelled` 以 request ID 關聯，表示結果不再使用、處理 SHOULD cease；2026-07-28 Streamable HTTP 以關閉該 request 的 response stream 表示 client 放棄 in-flight request。兩者都沒有提供 AgentPort Runtime 已停止的證據，因此 HTTP disconnect／request abort 不應自動標記 app Task canceled。**確定性：高。驗證：閱讀官方 2025 Schema 與 2026 Transports。未解：driver 如何取得停止證據、取消競賽裁定、外部副作用保留需 AgentPort contract tests。** [2025 cancellation schema](https://modelcontextprotocol.io/specification/2025-06-18/schema#notificationscancelled), [2026 transports cancellation](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports#cancellation)

- **工具資料契約包括 `inputSchema`、可選 `outputSchema`、`structuredContent` 與 `isError`。** 2026-07-28 Tools 要求每個 request 帶 `_meta` protocol version、client info、client capabilities；工具 execution errors 仍以 tool result 的 `isError: true` 表示，protocol errors 使用 JSON-RPC error。`structuredContent` 是 server-produced result data，不是 LLM structured output。**確定性：高。驗證：閱讀官方 2026 Tools。未解：caller 是否顯示／保留 structured result、AgentPort 各 operation schema 的實際 mapping 需測試。** [2026 Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [2026 specification overview](https://modelcontextprotocol.io/specification/2026-07-28)

- **HTTP auth 的完整 MCP conformance 不等於預配置 private bearer boundary。** 2026-07-28 Authorization 要求 protected resource metadata、authorization-server discovery、token audience validation，並要求 client 對每個 HTTP request 使用 `Authorization: Bearer`; authorization 本身仍是 OPTIONAL。AgentPort 可在受控 private deployment 採預配置 bearer／反向代理認證，但目前沒有證據能宣稱完整 OAuth MCP conformance；應把 OAuth discovery／token validation 視為 compatibility gate。**確定性：高。驗證：閱讀官方 2026 Authorization。未解：實際 caller 的 token provision、401 discovery、scope 與 audience 行為未測試。** [2026 Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)

- **SDK exact version 已可由 authenticated `gh` 驗證，但 target compatibility 尚未證明。** `gh auth status` 顯示已登入 GitHub；`gh release list --repo modelcontextprotocol/typescript-sdk` 列出 `@modelcontextprotocol/client@2.0.0`、`@modelcontextprotocol/core@2.0.0`、`@modelcontextprotocol/server@2.0.0`（2026-07-27）及 repository release `1.30.0`。官方 SDK migration page 說 v2 支援 2026-07-28。推薦實作時 pin exact v2 package versions，並以 2026-07-28 wire／auth／stateless probes 作 gate；不可使用 `latest` 或把 release metadata 當互通證明。**確定性：高（release metadata）；推薦：中。驗證：authenticated `gh auth status`、`gh release list`，並閱讀官方 SDK migration。未解：Linux Node baseline、Claude caller、dual-revision fallback、實際 Streamable HTTP 行為仍未 probe。** [SDK releases](https://github.com/modelcontextprotocol/typescript-sdk/releases), [SDK support 2026-07-28](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28)
