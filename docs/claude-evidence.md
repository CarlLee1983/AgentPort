# Claude Agent SDK 查證紀錄

查證日期：2026-09-12。範圍限 Anthropic 官方 Claude Code／Agent SDK 文件及官方 `anthropics/claude-agent-sdk-typescript` GitHub repository；未安裝 SDK、未啟動 Claude Code、未發送生成請求、未使用 Runtime／vendor 憑證，也未寫入外部服務。GitHub 僅以 authenticated `gh` 唯讀查詢取得公開 metadata。下列「已驗證」只代表官方來源明確記載，不代表 AgentPort 相容性測試已通過。

- **串流輸入是首版互動邊界（高確定度）。** 官方將 `prompt` 定義為 `string | AsyncIterable<SDKUserMessage>`；streaming input 是持續互動 session，支援 sequential queued messages、mid-task interruption、permission requests 與 session management。Single-message mode 明確不支援 dynamic queueing、real-time interruption 或自然多輪對話。已驗證：[Streaming Input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode#streaming-input-mode-recommended)、[TypeScript `query()` reference](https://code.claude.com/docs/en/agent-sdk/typescript)。缺口：尚未在 Linux 實際證明追加訊息會進入同一個 Task 的預期等待點。

- **輸出串流與輸入串流是不同契約（高確定度）。** `includePartialMessages: true` 會額外產生 `StreamEvent`；文字增量位於 `content_block_delta`／`text_delta`。一般輸出仍包含 `AssistantMessage` 與 `ResultMessage`。已驗證：[Streaming output](https://code.claude.com/docs/en/agent-sdk/streaming-output#enable-streaming)。缺口：未測量事件順序、背壓、斷線後是否仍能完整取得 final `ResultMessage`。

- **澄清問題可由 SDK 原生 AskUserQuestion 路徑承載（高確定度）。** 官方說明：Claude 的澄清問題使用 `AskUserQuestion`；它與工具批准都觸發 `canUseTool`，並在 callback 回傳前暫停 execution。辨識方式是 `toolName === "AskUserQuestion"`；若使用 `tools` 限制，必須包含 `AskUserQuestion`。Claude 產生問題及選項，應用程式負責呈現並回傳選擇；應用程式自己的問題要走獨立 application logic。已驗證：[Handle approvals and user input](https://code.claude.com/docs/en/agent-sdk/user-input#detect-when-claude-needs-input)。缺口：尚未驗證 AgentPort 問題 ID、首個有效回答、重送去重及 24 小時等待政策如何映射。

- **澄清與權限批准必須分開處理（高確定度）。** 同一 callback 的 `toolName` 仍區分兩種情況：普通工具（例如 `Bash`／`Write`）是 permission approval；`AskUserQuestion` 是 clarification。callback 的 TypeScript 形狀為 `CanUseTool(toolName: string, input: Record<string, unknown>, options: { signal: AbortSignal; suggestions?: PermissionUpdate[]; blockedPath?: string; decisionReason?: string; toolUseID: string; agentID?: string }): Promise<PermissionResult>`，回覆是 `{ behavior: "allow", updatedInput }` 或 `{ behavior: "deny", message }`。已驗證：[callback and response types](https://code.claude.com/docs/en/agent-sdk/user-input#respond-to-tool-requests)、[TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript#canusetool)。缺口：未定義 AgentPort 對超出既定執行權限的拒絕訊息及安全稽核欄位。

- **等待可無限期持續，取消才會解除 SDK 等待（高確定度）。** 官方指出 `canUseTool` callback 可 indefinitely pending；execution 保持 paused，SDK 只在 query 本身被 cancelled 時取消這個等待。長等待可用 `PreToolUse` hook 回傳 `defer`，讓 process 結束並從 persisted session resume。另有明確限制：`AskUserQuestion` 目前不可用於 Agent tool 產生的 subagents，且每次呼叫限 1–4 個問題、每題 2–4 個選項。已驗證：[input wait semantics and limitations](https://code.claude.com/docs/en/agent-sdk/user-input#handle-approvals-and-user-input)。缺口：未驗證中止中的工具、子代理及外層 process 是否全數停止。

- **`query()` 可在結果前取得控制權的可用形狀是 `Query` async handle（中高確定度）。** 官方 TypeScript reference 定義 `query(...) : Query`；官方 options 有 `abortController: AbortController`，而串流輸入的 async iterable 用於持續送入 follow-up／中斷方向。單一 query 的 permission／AskUserQuestion 在 loop 內處理，不會結束 call。已驗證：[TypeScript `query()` and `Options`](https://code.claude.com/docs/en/agent-sdk/typescript)、[session flow](https://code.claude.com/docs/en/agent-sdk/sessions#choose-an-approach)。缺口：reference 頁的全文大小限制使 Query interface 的全部方法未能逐項核對；不能據此宣稱存在某個特定 `.interrupt()` 方法。需以固定套件型別與 Linux contract test 核對「先取得 handle、再 await 結果」的實際用法。

- **Abort／子程序清理有明確延遲與責任邊界（高確定度）。** 官方 `SpawnOptions` 為 `{ command, args, cwd?, env, signal: AbortSignal }`；`SpawnedProcess` 必須提供 stdin/stdout、`killed`、`exitCode`、`kill(signal)` 及 exit/error listener。SDK 取消時先關閉 stdin、約等待兩秒讓 CLI clean shutdown，再 abort 傳給 custom spawn 的 `signal`；該 signal 不會在 `Options.abortController` 取消瞬間觸發，因此 wrapper 若要立即反應，必須另行監聽自己的 `abortController.signal`。已驗證：[TypeScript SpawnOptions／SpawnedProcess](https://code.claude.com/docs/en/agent-sdk/typescript#spawnoptions)、[官方 reference（signal cleanup note）](https://code.claude.com/docs/zh-CN/agent-sdk/typescript#spawnoptions)。缺口：SDK 契約沒有宣稱 process-group／cgroup 子樹清理；Linux wrapper 必須以 contract test 證明 child／grandchild 不殘留。

- **cwd、settingsSources、resume 的語意可查證，但不能當作跨重啟 exactly-once（高確定度）。** TypeScript `Options` 的 `cwd` 預設 `process.cwd()`；`settingSources` 可為 `"user" | "project" | "local"` 陣列，`[]` 停用這三類 filesystem settings，但 managed policy 仍會載入。`cwd` 決定 project/local 解析位置；CLAUDE.md／rules 會向父目錄搜尋。Session transcript 預設寫入本機，`resume` 依 session ID 恢復；跨主機需 `sessionStore` 或搬移 transcript，且 store lookup key 依 working directory。已驗證：[Use Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)、[Sessions](https://code.claude.com/docs/en/agent-sdk/sessions#resume-by-id)、[TypeScript Options](https://code.claude.com/docs/en/agent-sdk/typescript)。缺口：需固定版本核對 resume 後 settings／skills 載入、sessionStore flush 及工作目錄綁定；官方文件本身也提示跨主機需額外保存策略。

- **自訂 spawn 足以承接 Linux cgroup／container wrapper，但只是輸入契約（高確定度）。** 官方把 `spawnClaudeCodeProcess` 定義為 `(options: SpawnOptions) => SpawnedProcess`，用途包含 VM、container、remote environment；這支持把 `command/args/cwd/env/signal` 傳給受控 launcher。官方沒有承諾 cgroup、程序樹、網路或檔案隔離，也沒有提供 AgentPort 所需的停止證據。已驗證：[custom process spawning](https://code.claude.com/docs/en/agent-sdk/typescript#spawnclaudecodeprocess)、[SpawnOptions](https://code.claude.com/docs/en/agent-sdk/typescript#spawnoptions)。缺口：必須在 Linux 實際證明 wrapper 的 process-group/cgroup cleanup、停止時序及失聯狀態；本輪未執行。

- **版本可固定到官方目前 release，但不代表相容性已驗證（高確定度）。** authenticated `gh api repos/anthropics/claude-agent-sdk-typescript/releases/latest` 讀得官方 latest tag `v0.3.269`，發布時間 `2026-09-11T19:18:05Z`；文件另說 TypeScript V2 session API 已於 SDK `0.3.142` 移除，應使用 `query()`。已驗證：[official latest release](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.269)、[session API note](https://code.claude.com/docs/en/agent-sdk/sessions#typescript-continue-true)。缺口：目前沒有 package lock、Linux native optional dependency 安裝檢查或生成式 probe；實作前仍需在批准的 Linux 測試環境固定套件與 binary，並通過「先實際提問、取得回答、繼續同一 logical Task」正向驗收。
